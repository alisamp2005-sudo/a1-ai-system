# Бизнес-правила и архитектурные решения MVP

Данный документ фиксирует утвержденные решения по ключевым точкам логики системы. Все пункты согласованы с заказчиком и являются обязательными для реализации.

## 1. Поведение Router при отсутствии профильных AI-агентов (MVP)

Router классифицирует запрос (определяет тип и приоритет) и создает задачу на руководителя отдела из матрицы структуры компании. Руководитель получает уведомление в Telegram: "Новая задача: [тип]. Назначьте исполнителя или выполните сами." Это позволяет системе работать с первого дня, даже до подключения профильных AI-агентов.

## 2. Назначение исполнителя и дедлайна

Используется **фиксированная матрица** "тип задачи + объект → ответственный по умолчанию". Пример: задача по ТБ на объекте "Михалковская" автоматически назначается РП этого объекта. Дедлайн определяется из таблицы SLA по приоритету (P0 = 2ч, P1 = 8ч, P2 = 24ч, P3 = 12ч). ГД и топ-менеджмент могут переназначить исполнителя через кнопку "Делегировать".

## 3. Привязка задачи к объекту

Система использует гибридный подход из четырех шагов:

| Шаг | Условие | Действие |
|:---:|---------|----------|
| 1 | Router извлек название объекта из текста | Привязывает автоматически |
| 2 | Не удалось, но пользователь привязан к одному объекту | Назначает объект по умолчанию |
| 3 | Пользователь привязан к нескольким объектам | Бот спрашивает: "Уточните объект: [список кнопок]" |
| 4 | Общекорпоративный вопрос (HR, финансы) | Задача без объекта допускается |

## 4. Статусы задач и управление жизненным циклом

В MVP реализуются 5 статусов:

| Статус | Кто может перевести | SLA-таймер |
|--------|---------------------|:----------:|
| `new` | Система (при создании) | Тикает |
| `in_progress` | Исполнитель (принял задачу) | Тикает |
| `paused` | Руководитель, ГД (кнопка "Отложить") | Стоит |
| `done` | Исполнитель, Руководитель, Админ | Остановлен |
| `cancelled` | ГД, Руководитель | Остановлен |

Статусы "возвращена на доработку" и "делегирована" будут добавлены в Фазе 2 вместе с профильными AI-агентами.

## 5. Получатель эскалации на уровне 100% SLA

Получатель зависит от типа задачи:

| Тип задачи | Руководитель на 100% SLA |
|------------|--------------------------|
| Задача по конкретному объекту | РП этого объекта (из `projects.manager_id`) |
| Задача по отделу (HR, снабжение, ТБ) | Руководитель отдела (из `departments.head_id`) |
| Общая задача (поставлена ГД) | Зиновьева А. (Исполнительный директор) |

Для реализации в БД необходима таблица `departments` с полем `head_id` (FK -> users.id).

## 6. Изменение параметров задачи после создания

Изменение исполнителя, приоритета и дедлайна **разрешено** после создания задачи.

**Матрица прав на изменение:**

| Роль | Может менять |
|------|-------------|
| ГД (Алимов З.Т.), Зиновьева А., Лыков М.А. | Всё (исполнитель, приоритет, дедлайн) |
| Руководитель отдела | Задачи своего отдела |
| Исполнитель | Ничего (может только закрыть или запросить продление) |

**Правила пересчета SLA:**

| Изменение | Поведение SLA |
|-----------|---------------|
| Смена исполнителя | SLA перезапускается с нуля (новый человек получает полный срок) |
| Смена приоритета | SLA пересчитывается по новому приоритету от текущего момента |
| Смена дедлайна | SLA привязывается к новому дедлайну |

## 7. Обработка голосовых сообщений

Расшифровка голосового сообщения (Whisper) **не показывается** пользователю для подтверждения. Текст сразу направляется в Router. Обоснование: Whisper Large v3 дает точность ~95%+ на русском языке, а дополнительный шаг подтверждения ухудшает UX. Если Router не уверен в содержании, он задаст уточняющий вопрос (см. п.8).

Опционально: команда `/transcript` позволяет пользователю просмотреть последнюю расшифровку.

## 8. Поведение при низкой уверенности Router

При неоднозначных сообщениях система следует алгоритму:

| Ситуация | Действие |
|----------|----------|
| Уверенность Router < 70% | Бот спрашивает: "Уточните, это касается [вариант А] или [вариант Б]?" |
| Не определен объект | Бот спрашивает: "По какому объекту?" (кнопки) |
| Не определен исполнитель | Назначается по матрице (п.2) |
| После 2 уточнений всё ещё неясно | Задача создается в статусе `new` без привязки и уходит Зиновьевой А. на ручное распределение |

## 9. Формулировка требования конфиденциальности

> Все AI-модели (LLM, Whisper, Vision), обработка документов и база данных работают исключительно на локальном сервере компании. Данные не передаются сторонним AI-провайдерам (OpenAI, Anthropic, Google и др.). Telegram используется только как транспортный канал для доставки сообщений пользователям — содержимое сообщений проходит через серверы Telegram в зашифрованном виде.

## 10. Дополнительные правила SLA

| Правило | Описание |
|---------|----------|
| Выходные и праздники | SLA-таймер **не тикает** в нерабочее время (суббота, воскресенье, государственные праздники РФ) |
| Передача задачи | При смене исполнителя SLA перезапускается с нуля |
| Паузы | При статусе `paused` все таймеры останавливаются; при возобновлении — продолжают с того же места |
