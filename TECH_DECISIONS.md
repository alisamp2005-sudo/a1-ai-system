# Принятые технические решения (ADR - Architecture Decision Records)

В этом файле фиксируются ключевые архитектурные решения, чтобы не возвращаться к их обсуждению.

## 1. Выбор фреймворка для Агентов
- **Решение:** LangGraph
- **Альтернативы:** CrewAI, чистый Python, AutoGen
- **Обоснование:** CrewAI плохо работает с локальными моделями через Ollama (проблемы с JSON-схемами) и не поддерживает потоковую передачу (streaming) для чат-ботов. LangGraph дает полный контроль над состоянием (State), поддерживает циклы (для QA) и идеально подходит для чат-ботов.

## 2. Мультимодельная архитектура
- **Решение:** Qwen 32B (сложные задачи) + Llama 8B (простые задачи) + LLaVA 7B (Vision)
- **Альтернативы:** Одна модель Llama 70B для всего.
- **Обоснование:** Llama 70B занимает ~40 ГБ RAM. При добавлении Vision (LLaVA) на Mac Mini 64 ГБ начинаются проблемы с памятью и задержки на переключение моделей (выгрузка/загрузка с диска). Использование связки 32B + 8B снижает пиковое потребление до 49 ГБ, позволяя держать все модели в памяти одновременно.

## 3. Оборудование
- **Решение:** Mac Mini M4 Pro 64 ГБ
- **Альтернативы:** Mac Studio M4 Max 96 ГБ, PC с NVIDIA RTX 4090.
- **Обоснование:** Бюджет ограничен. Mac Mini M4 Pro 64 ГБ стоит ~$1400 (в 2.5 раза дешевле Mac Studio), но благодаря мультимодельной архитектуре (см. п.2) его памяти (64 ГБ) хватает с запасом в 15 ГБ.

## 4. Контроль SLA и Эскалация
- **Решение:** Celery + Redis
- **Альтернативы:** `asyncio.sleep()`, Cron, встроенные таймеры LangGraph.
- **Обоснование:** Эскалация требует надежности. Если сервер перезагрузится, `asyncio.sleep()` сбросится. Celery хранит отложенные задачи в Redis/БД, что гарантирует отправку уведомления даже после сбоя сервера.

## 5. Распознавание голоса
- **Решение:** Whisper Large v3 (локально)
- **Альтернативы:** Telegram Voice API, Yandex SpeechKit.
- **Обоснование:** Требование полной конфиденциальности. Аудио с совещаний не должно покидать контур компании.

## 6. Агент-Юрист: гибридная схема с Яндекс AI Юрист
- **Решение:** Подключаем Яндекс AI Юрист как внешний сервис. Наш агент работает как обертка: сначала ищет ответ в RAG-базе, если не найден — отправляет в Яндекс. Каждый ответ Яндекса сохраняется в RAG-базу (вопрос + ответ + контекст). Со временем агент накапливает базу знаний и отключается от Яндекса.
- **Альтернативы:** Полностью локальный юрист (Qwen 32B + RAG), полностью облачный (только Яндекс).
- **Обоснование:** Qwen 32B хорошо анализирует тексты, но не обучена на актуальном законодательстве РФ. Яндекс AI Юрист знает законы, но не знает документов компании. Гибридная схема дает лучшее из обоих миров: точные юридические ответы + контекст компании. По мере накопления базы (6-12 месяцев) зависимость от Яндекса снижается до нуля.
- **Алгоритм:**
  1. Пользователь задает юридический вопрос
  2. Агент ищет в RAG-базе похожий вопрос (confidence > 85%)
  3. Если найден → отвечает из базы (бесплатно, мгновенно)
  4. Если не найден → отправляет в Яндекс AI Юрист через API
  5. Ответ Яндекса сохраняется в RAG-базу для будущих запросов
  6. QA-Контролер проверяет ответ перед отправкой пользователю
- **Конфиденциальность:** В Яндекс отправляется только обезличенный вопрос (без названий объектов, ФИО, сумм). Контекст компании добавляется нашим агентом локально.

## 7. Vision-агент (анализ фото ТБ) — отложен
- **Решение:** Не включаем в MVP. Реализуем в Фазе 2 после стабилизации ядра.
- **Обоснование:** Vision требует дополнительной модели LLaVA 7B (~5 ГБ RAM) и сложной логики обработки изображений. Для MVP это не критично — контроль ТБ пока остается ручным.
